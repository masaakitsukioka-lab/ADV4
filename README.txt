工程19の追加：セーブの持ち運び
メニュー→「セーブの持ち運び」から操作します。

書き出す
・「今の進行を書き出す」：現在の探索状態をJSONにします。保存枠が空でも利用できます。
・「保存済みの記録を書き出す」：選んだ記録1〜3をJSONにします。
・1ファイルは1記録です。ブラウザのダウンロード先にファイルがあるか確認してください。
・未保存の進行と保存済み枠を取り違えないよう、ファイル名にcurrentまたはslot番号を含めます。
・ブラウザ保存領域が利用不可でも「今の進行を書き出す」は保存領域を使わず実行できます。

読み込む
1. 別のPC・ブラウザで本版のHTMLを開く。
2. メニュー→セーブの持ち運び→ファイルを読み込む。
3. JSONファイルを選択する（1MB以下）。
4. 場所・保存日時・持ち物数を確認し、取り込む記録1〜3を選択する。
5. 保存または上書きを確定する。キャンセル時は既存の記録を変更しない。
6. メニューの「ロード」から取り込んだ記録を選び、再開する。

取り込むだけでは現在のプレイを変更しません。保存日時は元データの日時を維持します。
壊れたJSONや別シナリオ・非対応の形式は拒否します。HTMLやスクリプトとしては実行しません。
ファイルは端末内で扱い、このゲームから外部へ送信しません。
ファイル選択を取り消す、確認画面でやめる、読み込み中に閉じる場合は、進行や記録を変更しません。
取り込みにはブラウザの保存領域が必要です。保存が拒否される環境でのファイルからの直接再開は未実装です。
Ver.0.10.0の保存形式との互換性はロジック検証済みです。Ver.0.10.0の画面自体には書き出し機能がありません。
前版のブラウザ内記録が本版から見えるかは、ブラウザ・HTMLの保存先に依存します。

工程18から引き継いだセーブ・ロード
・メニューに「セーブ」「ロード」を追加。手動保存は3枠です。
・保存対象：場所、フラグ、持ち物、訪問回数、一度きりのイベント実行履歴、文字速度、自動送り設定。
・会話と推理を終えてからメニューで保存してください。会話の途中位置は保存しません。
・ロードすると保存した場所の探索画面に戻ります。入室イベントを再実行せず、訪問回数も増やしません。
・既存枠の上書きとロードは確認画面を挟みます。自動保存・自動ロード・削除機能はありません。
・未保存の進行は再読み込みやロードで失われます。終了前に手動保存してください。

保存場所と制限
このブラウザの保存領域（localStorage）を使用します。外部には送信しません。
別端末・別ブラウザには自動共有されません。JSONファイルを書き出し、移動先で取り込んでください。
ブラウザのデータを消すとブラウザ内のセーブも失われます。
HTMLを直接開く場合、ブラウザやファイルの保存先によって保存領域の扱いが異なる可能性があります。
同じHTMLを同じ保存先・ブラウザで使い、保存→再読み込み→ロードを確認してください。
単体HTMLとZIP版などで保存領域が分かれる場合は、JSONファイルの書き出し・取り込みを使ってください。
保存不可・容量不足の場合は失敗メッセージを表示します。実ブラウザの保存確認は未完了です。

シナリオ編集時
meta.idはシナリオ識別子、meta.saveRevisionはセーブ互換性の番号です。
進行やフラグの意味を互換性のない形で変更した場合はsaveRevisionを増やしてください。
別の作品にする場合はidを変更してください。異なる識別子・互換性番号の記録は読み込みません。
今回のsaveRevisionは1、保存形式のformatも1です。Ver.0.10.0と保存形式は共通です。Ver.0.9.1以前にはセーブ機能がありません。
保存データの形式と既知の場所・フラグ・アイテム・イベントIDを検証します。
改ざん防止機能ではなく、すべての進行上の矛盾を検出するものではありません。

工程16から引き継いだイベント管理
・複数フラグ条件のAND / OR / NOTを入れ子で記述できます。
・場所ごとの訪問回数を管理し、入室時のイベントを実行します。
・会話選択肢からフラグ更新とアイテム付与ができます。
・idとonceで、一度きりのイベントを共通管理します。
・会話終了から選択肢表示までの遅延をなくし、探索操作が割り込む隙間を解消しました。

編集
実行時はscenario.jsを読みます。JSONを併用する場合は両方を同期してください。
この配布版では内容の一致を検証済みです。自動同期機能は追加していません。
単体版は配布時点の内容です。ZIP内のデータを編集しても単体版は更新されません。

イベントの共通項目（investigations、rooms[場所ID].onEnter、topics、choices）
 when : 条件。省略時は常に一致。
 set : {"フラグ名": true} のようなフラグ更新。
 give : 入手アイテム名の配列。重複追加しません。
 id : 一度きりのイベントを識別する、全イベントで重複しない文字列。
 once : trueならゲーム中一度だけ実行。idが必須。
 lines : [話者, 台詞, 表情]の配列。
 topic / next : 台詞のあとに進む会話ID。
 choices : 台詞のあとに表示する選択肢。
 分岐先はtopic、next、choicesのどれか一つを指定してください。

条件例
 {"shelfChecked": true, "noticeChecked": true}
  従来形式。すべて一致したときに成立。
 {"all": [{"flags": {"shelfChecked": true}}, {"not": {"flags": {"foundClue": true}}}]}
  両方が成立したとき。
 {"any": [{"flags": {"sketchDiscussed": true}}, {"flags": {"shelfDiscussed": true}}]}
  どちらかが成立したとき。
 {"visits": {"classroom": {"min": 2, "max": 4}}}
  美術教室への2〜4回目の訪問。数値だけなら回数が一致するとき。
 {"items": ["整理票の切れ端"], "done": ["shelf-clue"]}
  アイテムを所持し、指定したonceイベントが実行済みのとき。
 all / any / not / flags / visits / items / doneと同じ名前のフラグを使う場合は、flags内に記述してください。

実行ルール
調査と入室イベントは配列の上から最初に成立する1件を実行します。
条件不成立・実行済みonceイベントは読み飛ばします。
会話選択肢は成立するものだけを表示し、0件なら探索に戻ります。
set / give / onceの記録はイベント開始時（選択肢は選んだ時）に確定します。
開始場所の訪問回数は1。同じ場所を選び直しても増えません。
起動時の入室イベントは実行せず、移動・メニューを操作できる状態を維持します。
起動・再読み込み時は新規の探索画面です。メニューの「ロード」から保存済みの進行を再開できます。

試し方（仮シナリオ）
1. 美術教室の「机」を調べ、会話選択肢を選ぶ（sketchDiscussed / shelfDiscussedを更新）。
2. 「作品棚」を調べる。
3. 「いどう」から旧校舎の廊下へ移動し、「掲示板」を調べる。
4. 美術教室に戻ると再訪会話が一度だけ発生する。
5. 作品棚を再調査し、「整理票の切れ端」を入手する。
6. 再び廊下を往復しても再訪会話は繰り返さない。証拠も重複取得しない。
7. 作品棚で「しょうこをみせる」から既存の推理を進める。
